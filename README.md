# dsh-find-in-sessions

DeepSeek Harness 插件：`Ctrl+F` 呼出查找栏，按关键词检索**所有历史会话**的对话正文，命中后直接跳到那一段，用 F3 / ↑↓ 在命中之间前后跳。

## 为什么不用宿主自带的搜索

| 宿主自带 | 本插件 |
|---|---|
| 本机 profile 把 `session-query-sqlite` 配成 `openAt: never`，`/api/session/search` 一律返回 `SESSION_QUERY_SEARCH_DISABLED` | 自带搜索通道，直接读会话日志，不依赖那个索引 |
| `unicode61` tokenizer 把连续中文当一个 token，实测「插件」「本地搜索」命中数为 0 | 原生子串匹配，中文两字词照常命中 |
| 每个会话只返回一条最佳片段，没有事件坐标，只能打开会话 | 返回每条命中的 `seq` + `turn`，跳到具体那一轮并高亮 |

## 它是怎么快的

不建倒排索引。当前本机实测（1141 个会话文件 / 196.9 MB 压缩）：

| 项目 | 实测 |
|---|---|
| 只取 `user/assistant` 的 `text` 块 | 11,633 条 / 7.23 M 字符 |
| 内存里线性扫一遍 | 旧版 22.4 ms → **现在 0.6–4 ms** |
| 全量重读一个 12 MB 会话 | 108 ms（解压 41 + `JSON.parse` 52） |
| 增量重读同一会话 | **几 ms**（只解析新增事件） |
| 落盘快照（gzip JSON） | 3.8 MB |

两笔优化决定了手感：

1. **事件级增量**。会话日志是 append-only 的，`list()` 的 `sizeBytes` 变了就
   `read(已读事件数)` 只读新增那段，并在 meta 里记 `eventsRead` / `lastTurn` 接续解析。
   文件变小（rewind）或新增事件接不上 seq 时自动退回全量。当前会话每次搜索都在变，
   所以这一项直接决定「敲键后要等多久」。
2. **中文不做大小写折叠**。中文没有大小写，`toLowerCase()` 对它是纯浪费——实测
   22.4 ms 里有 21.7 ms 花在这一步，真正的 `includes` 只占 0.6 ms。现在只有含字母的
   关键词才查小写副本（按需构建一次），中文直接匹配原文。

## 用法

| 操作 | 键 |
|---|---|
| 打开查找栏 | `Ctrl+F`（当前会话）/ 双击 `Ctrl`（全部会话） |
| 关闭 | `Esc` |
| 在候选间移动 | `↑` `↓` / `F3` `Shift+F3` / `Shift+Enter`（上一处） |
| 打开选中的那一处 | `Enter`，或双击结果行 |
| 切换范围 | 点右侧「当前会话 / 全部会话」按钮 |
| 切换检索对象 | 点「正文 / 工具输出」按钮 |

上下键的行为分两种：

- **当前会话内**：边选边跳。命中就几处，跳转不换会话，翻起来连按即可。
- **全局检索**：`↑↓` 只移动选中，`Enter` 才跳过去——跨会话跳转会切走当前阅读位置、
  重建整屏，翻十条就是十次重建。这里与 IDE 的全局搜索一致。

`Ctrl+F` 原本是浏览器的页面内查找，本插件会拦掉它。


## 安装

```powershell
dsh plugin --profile web add <本目录或 tarball 路径>
```

装完重启 `dsh web`。插件同时有宿主半和浏览器半，两半都在启动时加载。

## 行为边界

- **只读会话，只写自己的缓存**：会话以 `read` 句柄打开，不改动会话文件；写入只有两个缓存文件
  （正文 `body.json.gz`、工具输出 `tool.json.gz`）。
- **两份快照，二选一**：正文与工具输出分开存、分开查，不混装——工具输出的体积是正文的数倍，
  混在一起会让扫描时间和内存都被拖垮。工具那份默认不建，第一次切到「工具」时才懒建（读全部会话，几秒）。
- **正文只索引看得见的正文**：`user/message`、`assistant/message` 里 `type: "text"` 的块；
  不索引 reasoning、工具调用参数、流式分片。`<system-reminder>` 注入块整块删除。
- **工具输出索引 `tool/result` 的文本块**，单条上限 20k 字符（一条 `rh` 或 `Get-Content`
  的输出可以到几 MB，全留会吃光内存）。
- **正文单条上限 200k 字符**，超长内容截断，避免一次工具转储吃掉几百 MB。
- **单次返回上限 200 条命中**；全局检索每个会话只采样 5 条，卡片上的「显示全部 N 条」
  会按同一条件再取一次该会话的全量。
- **跳转靠宿主自己的加载器**：`ISession.loadThrough(seq)` 拉历史页，`data-chat-turn` 做锚点。
  目标轮次还没渲染时提示而不会乱跳。
- **增量的两个边界**：会话级按 `sizeBytes` 判断变没变；`list()` 有 5 秒 TTL，
  所以正在写的会话要靠请求里带的 `sessionId` 额外 `stat` 一次才能立刻看到变化。
- **缓存不会自己过期**：会话变了会在下次搜索时增量重建；删掉文件只是触发一次全量重建。

## 已知限制

- 召回是字面子串，不是分词或语义：搜「本地搜索」不会命中「本地全文搜索」。
- 大小写不敏感（对含字母的关键词），但不做全半角、简繁、拼音归一化。
- 工具输出默认**不进索引**——它单独一份快照，要手动切到「工具」才会建立。
  首次切换要读完所有会话，几秒量级。
- 工具输出单条只留前 20k 字符，超长命令输出会被截断。
- 当前正在写的会话，最新几条可能还没落盘；再搜一次即可。

## 开发

```powershell
node --check lib/index.js
node --check lib/client.js
```

无构建步骤、无第三方运行时依赖：`lib/*.js` 就是分发产物。

`lib/client.js` 的 `Ctrl+F` 监听挂在 `window` 的 capture 阶段并 `preventDefault`，这是刻意的取舍，改动前先确认是否还要抢浏览器原生查找。
