# dsh-find-in-sessions

DeepSeek Harness 插件：`Ctrl+F` 呼出查找栏，按关键词检索**所有历史会话**的对话正文，命中后打开那一段，用 F3 / ↑↓ 在命中之间前后跳。

## 为什么不用宿主自带的搜索

| 宿主自带 | 本插件 |
|---|---|
| 本机 profile 把 `session-query-sqlite` 配成 `openAt: never`，`/api/session/search` 一律返回 `SESSION_QUERY_SEARCH_DISABLED` | 自带索引，直接读会话日志，不依赖那个库 |
| `unicode61` tokenizer 把连续中文当一个 token，实测「插件」「本地搜索」命中数为 0 | 中文按 bigram 切词，两字词照常命中 |
| 每个会话只返回一条最佳片段，没有事件坐标，只能打开会话 | 返回每条命中的 `seq` + `turn`，跳到具体那一轮并高亮 |

## 架构：SQLite 索引，不是内存快照

`lib/store.js` 用 Node 内置的 `node:sqlite` 建一个库（`~/.dsh/cache/dsh-find-in-sessions/index.db`），
FTS5 索引 + 自建中文 bigram 分词。

**为什么自己做 bigram**：`unicode61` 把连续中文当一个 token；`trigram` 按 3 字符切，
中文两字词凑不满窗口，索引用不上。入库前把中文切成两字窗口
（「会话搜索」→ `会话 话搜 搜索`），查询侧同样切。两字查询正好是一个 token，
三字以上是若干 token 的 AND。

**为什么不存整条消息**：长消息按 4000 字分块入索引，一条超长正文占多行。
旧版给正文 200k、工具 20k 的硬上限，超出直接切掉，导致「搜不到」和「不存在」在界面上
无法区分——现在不切了，行上会标「xx k · 第 k/m 段」。

本机实测（1141 个会话文件 / 196.9 MB 压缩 / 45.4 M 字符）：

| 项 | 实测 |
|---|---|
| 索引库 | 164.5 MB（正文 12602 行 + 工具 28513 行） |
| 当前会话内检索 | 6–8 ms |
| 全局 2 字中文 | 12 ms |
| 全局单 ASCII 词 | 10 ms |
| 全局 4 字以上中文 | 2–3 ms |
| 全局单字中文 | **575 ms**（无 bigram 可用，退化成全表扫） |
| 冷启动 | 0（不再解压解析 17.4 MB gzip） |

两条硬性性能约束写在 `store.js` 的 `search()` 里：`exact` 命中时不把 text 拉回 JS，
以及用 `MATERIALIZED` 保证 FTS 先跑（否则规划器会把 `instr` 排到前面，退化成 600 ms 的路径）。

**增量**：会话日志是 append-only 的，`list()` 的 `sizeBytes` 变了才进 `syncSession`，
它按 `read(已读事件数)` 只读新增那段，并在库里记 `size` / `events` / `turn` 接续。

## 用法

| 操作 | 键 |
|---|---|
| 打开查找栏 | `Ctrl+F`（当前会话）/ 双击 `Ctrl`（全部会话） |
| 关闭 | `Esc` |
| 在候选间移动 | `↑` `↓` / `F3` `Shift+F3` / `Shift+Enter`（上一处） |
| 打开选中的那一处 | `Enter`，或双击结果行（落点见下节） |
| 切换范围 | 点右侧「当前会话 / 全部会话」按钮 |
| 切换检索对象 | 点「正文 / 工具输出」按钮 |

上下键的行为分两种：

- **当前会话内**：边选边跳。命中就几处，跳转不换会话，翻起来连按即可。
- **全局检索**：`↑↓` 只移动选中，`Enter` 才跳过去——跨会话跳转会切走当前阅读位置、
  重建整屏，翻十条就是十次重建。这里与 IDE 的全局搜索一致。

`Ctrl+F` 原本是浏览器的页面内查找，本插件会拦掉它。

## 打开命中：四种落点

| 形态 | 落点 | 原因 |
|---|---|---|
| 当前会话 + 正文 + 消息数 ≤ 300 | 直接在对话里跳转并高亮 | 同一屏内挪动，比开个 tab 还快 |
| 当前会话 + 正文 + **消息数 > 300** | 右侧栏「命中预览」 | 宿主会话视图没有虚拟化，见下 |
| 全局检索 | 右侧栏「命中预览」 | 跨会话跳转会切走当前阅读位置、重建整屏 |
| 工具检索（任意范围） | 右侧栏「命中预览」 | 工具结果的 id 是 `callId`，会话视图里没有对应节点，跳过去必然落空 |

### 为什么超大会话不跳

宿主会话视图**没有虚拟化**：实测 `dsh-client-ui-conversation` 的 bundle 里
`Virtualizer` / `overscan` / `estimateSize` / `windowed` 全部零命中，`replaceWindow` /
`prepend` / `hasMore` 只是**数据分页**——消息一旦加载就全量挂成 DOM。

本机最长的一个会话有 6773 条消息（33.4 MB 压缩 → 91.4 MB 解压 / 37324 个事件）。
在这种容器上设一次 `scrollTop` 要把中间全部内容参与布局，浏览器直接卡死；
把**官方的滚动条**拖到顶部同样卡——这两件事说明卡点在渲染，不在检索，也不在跳转代码。

所以阈值为 300 条消息时就改走侧栏预览（纯文本，不碰会话渲染），并在状态栏说明原因。

### 不再有「退出回到原位」

「记 `scrollTop` 快照 → 退出时设回去」这一整套删掉了。它在无虚拟化容器上不成立：
设一次要等全部布局算完，清高亮会改变内容高度触发重排、宿主的「跟随末尾」
还会在下一帧再滚一次，于是只能靠 rAF + 120 ms 二次补设去抢，抢不抢得赢取决于宿主的
渲染时序——那就是「设了又被覆盖」反复出现的来源。现在跳过去就停在那儿。

## 安装

```powershell
dsh plugin --profile web add <本目录或 tarball 路径>
```

装完重启 `dsh web`。插件同时有宿主半和浏览器半，两半都在启动时加载。
只改 `lib/client.js` 时刷新页面即可；改 `lib/index.js` / `lib/store.js` 需要重启。

## 行为边界

- **只读会话，只写自己的索引**：会话以 `read` 句柄打开，不改动会话文件；写入只有
  `~/.dsh/cache/dsh-find-in-sessions/index.db`。旧的 `body.json.gz` / `tool.json.gz`
  不再读取，可以手工删掉。
- **两份索引，二选一**：正文与工具输出按 `kind` 分区存、分区查，不混装——工具输出的体积
  是正文的数倍，混在一起会让索引膨胀、查询变慢。工具那份默认不建，第一次切到「工具」
  时才懒建（读全部会话，几秒），建好后常驻磁盘而不是常驻内存。
- **正文只索引看得见的正文**：`user/message`、`assistant/message` 里 `type: "text"` 的块；
  不索引 reasoning、工具调用参数、流式分片。`<system-reminder>` 注入块整块删除。
- **工具输出索引 `tool/result` 的文本块**，不再截断（旧版单条 20k 上限已取消）。
- **单次返回上限 200 条命中**；全局检索每个会话只采样 5 条、最多 60 个会话，
  卡片上的「显示全部 N 条」会按同一条件再取一次该会话的全量。
- **跳转靠宿主自己的加载器**：`ISession.loadThrough(seq)` 拉历史页，`data-chat-turn`
  做锚点。目标轮次还没渲染时提示而不会乱跳。
- **增量的边界**：会话级按 `sizeBytes` 判断变没变；`list()` 有 5 秒 TTL，
  所以正在写的会话要靠请求里带的 `sessionId` 额外 `stat` 一次才能立刻看到变化。
- **库不会自己过期**：会话变了会在下次检索时增量对齐；会话文件消失会在下次整体对齐时
  从库里清掉。切词规则或表结构变化时 `INDEX_VERSION` 递增，旧库整份丢弃重建。

## 已知限制

- 召回是**字面子串**，不是分词或语义：搜「本地搜索」不会命中「本地全文搜索」。
- 大小写不敏感（对含字母的关键词，由 FTS 的 `unicode61` 折叠），但不做全半角、简繁、拼音归一化。
- **单字中文很慢**（~575 ms）：一个汉字凑不出 bigram，FTS 用不上，只能全表 `instr`。
  三字以上中文会切出多个 bigram，需要回原文复验（`instr`），比两字慢但仍是毫秒级。
- 工具输出默认**不进索引**——它单独一份，要手动切到「工具」才会建立。
  首次切换要读完所有会话，几秒量级。
- 当前正在写的会话，最新几条可能还没落盘；再搜一次即可。
- 索引库体积随语料线性增长（本机 45.4 M 字符 → 164.5 MB）。这是「不常驻内存」的代价。

## 开发

```powershell
node --check lib/index.js
node --check lib/client.js
node --check lib/store.js
```

无构建步骤、无第三方运行时依赖：`lib/*.js` 就是分发产物。`lib/store.js` 依赖 Node 内置的
`node:sqlite`（Node 22.5+ 提供，本机 v24 已稳定）。

`lib/client.js` 的 `Ctrl+F` 监听挂在 `window` 的 capture 阶段并 `preventDefault`，这是刻意的取舍，改动前先确认是否还要抢浏览器原生查找。
